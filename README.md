# 台本のまえに

ショート動画の企画に必要な情報を整理し、AIに台本を依頼するための指示書（プロンプト）を作成するアプリです。

「どんな人の、行動しない理由を、どんな動画で取り除き、何につなげるか」を順番に入力することで、TikTok向けの30秒〜1分程度の動画の狙いを明確にします。初期設定は、プログラミングスクールSUNABACOの集客担当者向けとします。

## 開発状況

初期版を実装済みです。指示書の生成・直接編集・コピーに対応しています。AI接続や台本そのものの生成は行いません。ローカルアプリとして実装し、公開はしていません。起動方法と検証状況は末尾を参照してください。

## 目的

- 誰に何を伝える動画なのかを、制作前に明確にする。
- 視聴者が行動しない理由に合わせて、動画形式と訴求を選べるようにする。
- 入力内容を指定テンプレートにまとめ、台本を依頼しやすくする。
- 認知、信頼、ファンづくりを通じて、受講申し込みや集客などの目的につなげる。

## 初期版の範囲

初期版では、フォームの入力内容から指示書を組み立て、プレビュー・コピーできるところまでを実装します。指示書を生成AIに渡して台本を作成することを想定します。

アプリ内でのAIによる台本生成、動画編集、TikTokへの投稿、投稿結果の分析は初期版の対象外です。指示書の組み立て自体にはAI接続を必要としません。

## 利用の流れ

1. 所属・役割と、動画で達成したい目的を入力する。
2. 対象者の認知・関心の段階と、具体的な人物像を選ぶ・入力する。
3. 行動しない理由を選び、その人が感じている不安や疑問を具体化する。
4. 提示された動画形式・訴求の候補から選び、必要に応じて編集する。
5. 集客・受講申し込みにつながらない具体的な理由を整理する。
6. 指示書を生成し、内容を確認してコピーする。

## 入力項目

| 項目 | 入力方法・初期値 | 用途 |
| --- | --- | --- |
| 所属・役割 | テキスト。初期値：プログラミングスクールSUNABACOの集客担当者 | 指示書の冒頭 |
| 投稿先 | 初期版はTikTok固定 | 動画の媒体 |
| 対象者の段階 | 下記の3段階から1つ選択 | 人物像を考える補助 |
| どんな人 | 必須テキスト | 視聴者の具体的な人物像 |
| 行動しない理由 | 下記の5分類から1つ選択し、具体的な理由を必須入力 | 取り除きたい障壁 |
| どんな動画 | 候補から選択または自由入力。必須 | 動画形式・ジャンル |
| 目的 | 必須テキスト | 視聴後に起こしてほしい変化・行動 |
| 集客に繋がらない理由 | 必須テキスト。受講申し込みにつながらない発信側の課題を記入 | 発信内容・導線の課題 |
| どんな訴求 | 候補から選択または自由入力。必須 | 課題を解消する伝え方 |
| 動画の長さ | 初期版は「30秒〜1分程度」固定 | 台本の尺 |
| 行動喚起（CTA） | 任意。保存、いいね、フォロー、講座の詳細の確認など | 最後に促す具体的な行動 |
| 使用できる事実・素材 | 任意テキスト | 掲載許可のある受講者の声、撮影可能な場面、確認済みの情報など |

「行動しない理由」は視聴者側の障壁、「集客に繋がらない理由」は発信側の課題として区別します。例：前者は「未経験でも学習についていけるか不安」、後者は「講座の案内だけで授業の雰囲気が伝わっていない」です。

### 対象者の3段階

| 段階 | 状態 | 集客での読み替え例 |
| --- | --- | --- |
| 知らない人 | 潜在的なニーズがある可能性がある | SUNABACOや講座を知らない人 |
| 知っているが興味がない人 | 必要性や自分との関係を感じていない | SUNABACOは知っているが、自分が学ぶ場所として考えていない人 |
| 興味はあるが行動しない人 | 不安や行動のハードルがある | 学習に興味はあるが、受講をためらっている人 |

段階だけで行動しない理由を決めつけず、具体的な人物像と合わせて入力します。

### 行動しない理由と、動画・訴求の候補

添付資料の5分類を、選択肢と候補提示の基礎として使用します。「商品」はスクール集客では講座や学習体験、「利用者」は受講者などに読み替えます。

| 行動しない理由 | 訴求の方向性 | 動画形式の候補 |
| --- | --- | --- |
| 商品に納得していない | 望む未来につながる根拠を示す | 受講者インタビュー、変化のドキュメンタリー、第三者の推薦、データ・実績紹介 |
| 発信者を信用していない | 人柄・想い・専門性を伝える | 仕事への想いを語るストーリー、日常や裏側、役立つ情報、Q&A |
| 会社を信用していない | 組織の信頼性・透明性・安心感を伝える | 代表のストーリー、講師紹介、授業風景、教室ツアー、確認済みの掲載・受賞実績、地域活動 |
| 行動のハードルが高い | 手順を具体化し、不安を解消する | チュートリアル、体験の様子、体験機会の紹介、変化のドキュメンタリー、FAQ |
| 商品の必要性に気づいていない | 自分との関係や新しい気づきを伝える | 役立つ知識、思い込みを見直す解説、よくある失敗と改善例 |

候補は選び直し・自由編集を可能にします。実績、推薦、体験制度、受講条件などは、実在を確認できる場合にのみ使用します。添付資料の強い断定表現は、そのまま必須の表現にはしません。

## 生成する指示書

### 基本テンプレート

以下の構成を維持し、【】の部分を入力値に置き換えます。初期設定と入力例はスクール集客向けです。

```text
私は【所属・役割】です。

TikTokショート動画を作ります。

### 動画の目的とジャンル

【どんな人】の【行動しない理由】を【どんな動画】で取り除いて

【目的】

### 動画の内容

【集客に繋がらない理由】を、【どんな訴求】で解決する。

### 動画の長さ

30秒〜1分程度

効果的な台本を提案してください。
```

### 任意の補足

CTAや使用できる事実・素材を入力した場合は、基本テンプレートの末尾に「補足条件」として追記します。未入力の項目は出力しません。

「台本の構成・演出条件を追加する」を有効にした場合は、次の条件を追記します。初期状態は有効とし、基本テンプレートだけの出力にも切り替えられるようにします。

```text
### 台本の構成・演出条件

- 冒頭で対象者が自分に関係する内容だと分かるようにしてください。
- 視聴維持を意識し、1本で伝える主題を絞ってください。
- 行動しない理由に共感し、具体的な説明や根拠で不安・疑問を解消してください。
- 動画の目的に合う行動喚起を1つに絞ってください。指定があれば優先してください。
- エフェクトは強調したい箇所のアクセントとして使ってください。
- 秒数、セリフ・ナレーション、映像、テロップ、演出を表で提案してください。
- 全体が30秒〜1分に収まる構成にしてください。
- 未提供の実績、数値、体験談、受講条件は創作せず、必要な箇所を「要確認」としてください。
```

視聴維持、反応を促す行動喚起、アクセントとしてのエフェクトは、ユーザー提示の制作方針として扱います。おすすめ表示や集客成果を保証する仕様にはしません。

### 生成例（架空の企画）

以下は入力・出力を説明する例であり、SUNABACOの実際の講座内容や学習環境を示すものではありません。

```text
私はプログラミングスクールSUNABACOの集客担当者です。

TikTokショート動画を作ります。

### 動画の目的とジャンル

プログラミングに興味はあるが受講を迷っている人の、未経験でも学習についていけるか分からないという不安を、学習の進め方と授業風景を紹介する動画で取り除いて

講座の詳細を確認してもらう。

### 動画の内容

講座の案内だけでは学習の進め方や授業の雰囲気が伝わらず、受講申し込みに繋がらないことを、確認済みの学習内容と実際の授業風景による安心感の訴求で解決する。

### 動画の長さ

30秒〜1分程度

効果的な台本を提案してください。
```

## 画面・操作

- 入力フォーム：項目ごとに短い説明と記入例を表示する。
- 候補表示：行動しない理由に応じて、動画形式・訴求の候補を表示する。選択済みの内容を無断で上書きしない。
- 生成ボタン：必須項目を確認し、入力値から指示書を生成する。
- 出力プレビュー：生成内容を確認・編集できるようにする。
- コピーボタン：プレビューの全文をコピーし、成功・失敗を表示する。
- 再生成：入力を修正して再生成できる。プレビューを直接編集している場合は、上書き前に確認する。
- リセット：入力と出力を初期状態に戻す。入力済みの場合は確認する。

スマートフォンとパソコンの両方で、入力からコピーまで操作できる画面を想定します。

## 初期版の完成条件

- 必須項目が未入力・空白のみの場合、該当箇所と不足内容を表示する。
- 3段階の対象者と5分類の障壁を選択できる。
- 選択した障壁に対応する動画形式・訴求の候補を確認できる。
- 入力内容が指定テンプレートの対応箇所に反映され、未置換のプレースホルダーが残らない。
- 所属・役割の初期値と「30秒〜1分程度」が出力に反映される。
- 任意項目の未入力で、不自然な空欄の見出しが出力されない。
- 補足条件の有無を切り替えられる。
- プレビューの内容をコピーでき、失敗時は手動コピーを案内できる。
- 入力値や編集内容を、再生成・リセットで意図せず失わない。

## 実装・起動方法（2026年10月30日）

HTML / CSS / JavaScript（ES Modules）とNode.js標準機能で構成しています。外部依存パッケージやAPIキーは不要です。Node.js 20以上を使用してください。

```sh
npm run dev
```

表示された http://localhost:5173 をブラウザで開きます。停止はターミナルで Ctrl+C。ポートを変更する場合は `PORT=5174 npm run dev` を使用します。ES Modulesを使用するため、HTMLファイルを直接開くのではなくHTTPサーバー経由で利用してください。

```sh
npm test       # 生成ロジックのテスト
npm run build # dist/ に配信用の静的ファイルを出力
```

公開する場合は `dist/` をHTTPS対応の静的ホスティングへ配置できます。

### 実装済み

- 3段階の認知・関心、5分類の障壁、必須7項目、任意のCTA・事実素材。
- 障壁に応じた動画形式・訴求の候補。分類を変更しても既存入力を保持し、候補で置き換える際は確認。

## 台本ディレクターへの引き継ぎ改善

添付された「ショート動画台本ディレクター」に指示書を貼り付けて台本を依頼する流れを標準にしました。

- 認知・関心の3段階と障壁の5分類を、人が読める名称で基本テンプレート末尾に追記します。
- 任意項目に「視聴後に持ってほしい気持ち」「撮影・編集の条件」を追加しました。空欄は出力しません。
- 渡し先の初期値は台本ディレクターです。企画の要約、フック、台本、制作メモ、次回検証を依頼し、演出の細部はエージェントに委ねます。未提供の事実・URL・インタビュー発言を創作しない条件を含めます。
- 「一般の生成AI・基本テンプレート」を選ぶと、従来の構成・演出条件のオン・オフを利用できます。エージェント向けではこの条件を重複出力しません。
- 必須項目の入力進捗と、生成後の入力変更を表示します。直接編集と入力変更が同時にあっても、再生成が必要なことを別の案内で表示します。
- コピー後の貼り付け先と確認手順を案内します。エージェントへの自動送信・AI接続は行いません。

## GitHub Pagesでの公開

アプリ名は「台本のまえに」、リポジトリ名・パッケージ名は `daihon-no-maeni` とします。GitHub上の公開先リポジトリは未登録です。

`.github/workflows/pages.yml` を追加しています。`main` へのpushまたは手動実行により、テスト → ビルド → `dist/` の公開を行います。アプリの配信用ファイルのみをアップロードし、参照資料やREADMEはPagesの成果物に含めません。CSS・JavaScriptは相対パスで参照するため、リポジトリ名を含むURLでも動作する構成です。

初回はGitHubリポジトリへソースを登録し、Settings → Pages → Build and deployment → Sourceで **GitHub Actions** を選択します。その後、Actionsの **Deploy to GitHub Pages** を実行します。成功すると公開URLが表示されます。
